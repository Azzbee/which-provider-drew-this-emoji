# Emoji provider classification

Course project for **IDSI51006 Computer Vision** (BSc AIDAMS, ESSEC x CentraleSupélec, 2026), team **The Winners**
(Adam Zeraiki, Lina Oumhand, Charles, Erdem Sanver). Given a PNG of an emoji, predict which provider drew it:
`apple, facebook, google, messenger, mozilla, samsung, whatsapp`. 9,879 labelled training images, 9,879 test images,
metric = accuracy on the Kaggle competition.

Every verified number in the paper (`../paper/Paper_The_Winners.pdf`) is produced by this codebase. `AI_USAGE.md` lists
every AI tool used on the project and the prompts.

## Final model and results (all numbers regenerated by `scripts/build_report_tables.py`)

Final model: **ConvNeXt-Tiny (ImageNet-1k weights, `timm` name `convnext_tiny.fb_in1k`) fine-tuned at 224 px, 5 folds,
fixed 10-epoch OneCycle budget with the last epoch kept (no checkpoint selection), horizontal-flip test-time augmentation,
equal-weight soft vote of the five fold-models** (`outputs/convnext224_last`, run B). Trained on an NVIDIA RTX 4090
(RunPod, 17 Oct 2026), about 2.6 minutes per fold. Run A (same trainings, lowest-validation-loss epoch kept) is the
ablation that showed why: the two runs reproduced each other to the last decimal at every epoch (same seeds, same GPU,
`cudnn.deterministic`), so the 0.4-point gap is entirely the choice of epoch.

| Model | Validation protocol | Accuracy |
|---|---|---|
| Majority class | stored split (1,979 images) | 19.6% |
| File metadata only, no pixels: width, height, PNG mode, alpha flag (logistic regression / random forest) | stored split | 64.6% / 66.4% |
| File metadata only, + file size, transparent fraction, colour under transparent pixels (random forest) | stored split | 87.4% |
| September baseline `EmojiCNN` (re-scored checkpoint) | stored split | 76.71% (1,518 / 1,979) |
| `EmojiCNNv2` (0.39 M parameters, 96 px) | stored split | 90.96% |
| `EmojiCNNv2` + file metadata (late fusion) | stored split | 93.38% |
| ConvNeXt-Tiny 224 px, run A (5 folds, checkpoint = lowest validation loss), ablation | out-of-fold, 9,879 images | 97.29% |
| **ConvNeXt-Tiny 224 px, run B (5 folds, checkpoint = last epoch), the final model** | out-of-fold | **97.69%** (macro F1 0.977) |
| Runs A + B averaged (10 checkpoints), ablation | out-of-fold | 97.70% |

Public leaderboard (verified on Kaggle, 18 Oct 2026): baseline 0.77546, EmojiCNNv2 0.90747, fusion 0.93824,
**0.98319 for the final model** (`outputs/submissions/submission_convnext224_last.csv`) and 0.98279 for the
ten-checkpoint average (`submission_convnext224_AB_10models.csv`). Private leaderboard after the close: 0.98218 for the
final model and 0.98198 for the average. The team's two selected entries were the final model and Erdem's E15
(0.98238 private), which ranked the team 5th of 18.

## Run it

### Any Linux box with an NVIDIA GPU (what we did: a RunPod RTX 4090 pod, PyTorch 2.8.0 template), about 35 minutes

```bash
# on the pod, in /workspace: the Kaggle archive and this folder (unzipped as codebase/)
cd /workspace/codebase
sha256sum ../2-computer-vision-2026-b-sc-aidams-final-proj.zip   # 7f8c12a2a36591e45f761b21a49dc2e9be1276e7d04cbf6d06ca8df2d844ad8d
pip install -r requirements-gpu-runtime.txt                       # scikit-learn + timm on top of the image's torch
# run A: per fold keep the epoch with the lowest validation loss (the default)
python scripts/train_backbone.py --zip ../2-computer-vision-2026-b-sc-aidams-final-proj.zip --data-dir ../data/extracted \
       --out outputs/convnext224 --workers 8 --folds 5 --epochs 10 --size 224 --batch 32 --lr 2e-4
# run B: keep the last epoch (OneCycle has annealed the learning rate to ~0 by then)
python scripts/train_backbone.py --zip ../2-computer-vision-2026-b-sc-aidams-final-proj.zip --data-dir ../data/extracted \
       --out outputs/convnext224_last --workers 8 --folds 5 --epochs 10 --size 224 --batch 32 --lr 2e-4 --select-on last
# ablation: equal-weight soft vote of both checkpoint sets (10 checkpoints); the final entry is run B's own submission.csv
python scripts/make_final_submission.py outputs/convnext224/test_proba_mean.npy outputs/convnext224_last/test_proba_mean.npy \
       --data-dir ../data/extracted --out outputs/submissions/submission_convnext224_AB_10models.csv \
       --compare outputs/convnext224_last/submission.csv
```

Each run took about 16 minutes on the RTX 4090 (13 minutes of training, the rest is decoding the 19,758 PNGs once,
inference with TTA and the figures). Pretrained weights are fetched from the Hugging Face hub by `timm` on first use.
The same commands work on any CUDA machine; on a T4 expect roughly 4x the training time.

### Google Colab (GPU)

Upload both zips to `/content`, pick a GPU runtime, open the notebook, run all. The submission downloads automatically.

### Databricks (GPU)

Upload the two zips to a Unity Catalog Volume, import the notebook, attach a GPU cluster with an ML runtime, set
`CODEBASE_ZIP` and `ZIP_PATH` in the notebook to the `/Volumes/...` paths, run all; the last cell copies `outputs/` back
to the Volume. (The Metalab workspace we had access to had no Unity Catalog and no A100 quota on 17 Oct, which is why the
final runs were done on RunPod.)

### Laptop (CPU, for the ladder and smoke tests)

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp ~/Downloads/2-computer-vision-2026-b-sc-aidams-final-proj.zip data/
python scripts/run_cpu_experiments.py --zip data/2-computer-vision-2026-b-sc-aidams-final-proj.zip --out outputs/cpu
python scripts/train_backbone.py --smoke --out outputs/smoke_gpu          # checks the GPU recipe's code path in minutes
python scripts/make_final_submission.py outputs/cpu/test_proba_emojicnnv2.npy --out outputs/submissions/cpu_only.csv
python -m pytest tests -q
```

Apple Silicon: the scripts use the MPS backend automatically; ConvNeXt-Tiny at 224 px takes roughly 2 h per fold on an M4.

## Decisions worth knowing (details and evidence in the report)

* **Alpha-composite on white, keep aspect ratio, pad.** Default RGB loading drops the alpha channel and exposes a
  provider-specific colour hidden under transparent pixels; we remove that shortcut on purpose.
* **Group-aware validation.** 158 training images are exact duplicates; `StratifiedGroupKFold` on the pixel hash keeps
  copies on one side of the split.
* **Only exact-pixel augmentation** (flip, integer shift). Resampling-based augmentation blurs the anti-aliased outlines
  that distinguish providers (Erdem's E7 lost 1.5 points with rotation/scale + label smoothing).
* **File format is a measured shortcut, not a feature of the final model.** Native size and PNG mode alone give 64 to
  66% validation accuracy without looking at a single pixel, and 87% once file size, transparent fraction and the colour
  under transparent pixels are added. The final model sees only pixels; the fusion ablation quantifies what metadata adds.
* **Checkpoint selection matters at this accuracy.** Selecting the epoch with the lowest validation loss (run A) kept
  epochs 4 to 8 while validation accuracy was still rising; keeping the last epoch (run B, same trajectories) gained
  0.4 points out-of-fold and is the final model. Averaging both checkpoints of every fold was a tie (97.70%) and
  scored lower on the public board (0.98279 vs 0.98319).
* **Post-processing rules are off by default.** 333 test files are byte-identical to training files; a lookup rule and
  a within-test consistency rule exist in `submit.py` and were not used for the final entry (0 predictions changed).
