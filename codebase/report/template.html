1. Summary

The task is to recognise the vendor of an emoji image, not the emoji itself: a plate of spaghetti drawn by Apple and the same plate drawn by Google show the same object, so what separates the classes is rendering style (outline thickness, shading, gradients, palette) rather than content. We treat it as a 7-class image classification problem and solve it with a convolutional neural network.

Three findings shaped the work. First, the files leak the answer: each provider exported its emoji at its own resolution (72 px for Apple, Google and Samsung, 160 px for WhatsApp, 240 px for Facebook, Messenger and Mozilla) and in its own PNG mode, and a classifier that reads only the file's dimensions and colour mode, never a pixel, reaches {{ meta_format.accuracy|pct if meta_format else "well above chance" }} validation accuracy, and {{ best_meta.accuracy|pct if best_meta else "more" }} once file size, the share of transparent pixels and the colour hidden under them are added, still without looking at the drawing verified. We therefore preprocess every image onto the same white square canvas so that the network is judged on how it sees, not on the export pipeline, and we keep the metadata model as a diagnostic only. Second, the default way of loading PNGs drops transparency and exposes a vendor-specific colour hidden under transparent pixels; alpha-compositing on white fixes it and improves a from-scratch CNN by 1.5 points reported. Third, 158 training images are exact duplicates and 333 test files are byte-identical to training files, so validation is done with a group-aware split that keeps copies together.

Our ladder goes from a majority-class guess ({{ cpu.majority_class.accuracy|pct if cpu else "19.5%" }}) to the team's first CNN ({{ base.accuracy|pct(2) if base else "76.71%" }} verified), a compact four-stage CNN trained from scratch ({{ v2.accuracy|pct(2) if v2 else "pending" }} {{ 'verified' if v2 else 'pending' }}), and ImageNet-pretrained backbones fine-tuned end to end, where resolution turned out to matter more than architecture ({{ e8.val_accuracy|pct(2) if e8 else "97.57%" }} for ConvNeXt-Tiny at 224 px reported). The final model is ConvNeXt-Tiny fine-tuned at 224 px, trained in 5 folds for a fixed 10-epoch budget (the last epoch is kept, no checkpoint selection) and averaged with horizontal-flip test-time augmentation{% if fin %}: {{ fin.accuracy|pct(2) }} out-of-fold accuracy over {{ "{:,}".format(fin.n) }} images, macro F1 {{ fin.macro_f1|num }} verified{% else %} pending{% endif %}, and {{ N.public_lb.final_entry.public_score|num(5) if N.public_lb and N.public_lb.final_entry else "" }} on the public leaderboard, the team's best entry verified. Along the way we found that the usual rule of keeping the lowest-validation-loss epoch cost 0.4 points here, because validation loss and accuracy diverge once the network becomes over-confident (Section 5.2). The three CPU files produced by this codebase score 0.77546, 0.90747 and 0.93824 on the public board, each within half a point of its validation accuracy verified.

Model chosen

Type: convolutional neural network (CNN). Final entry: ConvNeXt-Tiny (Liu et al., 2022; 28 M parameters), initialised from ImageNet-1k weights and fully fine-tuned on 224 × 224 inputs; 5 fold-models (one per fold, final epoch of a fixed 10-epoch schedule) averaged (soft voting) with horizontal-flip TTA. Reference model: EmojiCNNv2, a 0.39 M-parameter CNN trained from scratch at 96 px, used for ablations and explainability.

Not a vision-language model. VLMs are trained to describe what is in an image; here every class contains the same objects and the signal is low-level drawing style, exactly what the early convolutional filters of a CNN capture. A CNN is also cheaper (minutes to an hour of training), easier to inspect (Grad-CAM, per-class confusion) and easier to reproduce, which matches the brief's advice to prefer something simple that we master.

Not hand-crafted features. Colour histograms + HOG with an SVM reached {{ (rep.experiments | selectattr("id","equalto","E1b_hog_color_svm") | first).val_accuracy|pct if rep else "81%" }} reported, well below any CNN we trained.

So a model can score far above chance without recognising any drawing style. We consider this a property of how the dataset was built, not of the providers' art, and we took two decisions: (i) every image is composited on white and placed on a square canvas of one size, which removes the hidden-colour cue and makes the canvas identical for all classes; (ii) the file-metadata model is reported as a diagnostic and the final model sees pixels only. 2.3 Preprocessing recipe

One function (emoji_provider.data.load_rgb_white) feeds every model:

  1. Decode as RGBA and alpha-composite on a white background. This is how a chat application renders an emoji on a light bubble, and it discards the colour hidden under transparent pixels (Figure 3). Erdem measured the effect on the from-scratch CNN: {{ (rep.experiments | selectattr("id","equalto","E2_simple_cnn_naive") | first).val_accuracy|pct if rep else "92.1%" }} with naive RGB loading versus {{ (rep.experiments | selectattr("id","equalto","E3_simple_cnn_white") | first).val_accuracy|pct if rep else "93.6%" }} with white compositing, everything else equal reported.
  2. Fit inside a square keeping the aspect ratio, pad with white. A few Google files are 72x68 or 66x72; stretching them would distort stroke widths, so we use ImageOps.contain (Lanczos) and centre the result on a white square.
  3. Resize to the model's input size (96 px for the small CNN, 224 px for ConvNeXt-Tiny) and store as uint8. The arrays are cached as .npy so that a rerun does not decode 19,758 PNGs again.
  4. Normalise with ImageNet mean and standard deviation for the pretrained backbone, and to [-1, 1] for networks trained from scratch.

We deliberately did not crop, did not convert to grayscale (colour palettes are part of the style) and did not equalise histograms.

2.4 Data augmentation

The vendor signature lives in anti-aliased outlines, gradients and exact colours. Any augmentation that resamples the image (rotation, scaling, elastic warps) blurs precisely those cues, and colour jitter destroys palette information. Erdem tested rotation ±10°, 5% shifts, 0.9 to 1.1 scaling and label smoothing on ConvNeXt-Tiny at 128 px and lost 1.5 points ({{ (rep.experiments | selectattr("id","equalto","E6b_convnext_tiny_finetune") | first).val_accuracy|pct if rep else "95.9%" }} to {{ (rep.experiments | selectattr("id","equalto","E7_convnext_tiny_aug") | first).val_accuracy|pct if rep else "94.4%" }}) reported; because three things changed at once that experiment is not conclusive about which one hurt, but it is consistent with the reasoning.

We therefore use only exact-pixel augmentation: a horizontal flip with probability 0.5 and an integer translation of at most 4 px obtained by padding with white and cropping. Neither operation interpolates, so an outline that is 1.3 px wide stays 1.3 px wide. Augmentation is applied on the fly to training images only. For the compact CNN trained from scratch, which overfits quickly on 7,900 images, this is the main regulariser besides dropout and weight decay.

2.5 Duplicates and validation protocol

Hashing the preprocessed pixels shows {{ eda.pix96_duplicate_images_beyond_first if eda else 158 }} training images that are exact copies of another training image ({{ eda.raw_duplicate_images_beyond_first if eda else 149 }} are byte-identical files), always with the same label ({{ eda.pix96_conflicting_groups if eda else 0 }} conflicting groups). A random split would place copies on both sides and inflate validation accuracy. We use StratifiedGroupKFold with the pixel hash as the group, so identical images stay together and class proportions are preserved. The split used by every single-model experiment (7,900 train / 1,979 validation, seed 42) is stored as data/split_seed42.csv; we ship the file because the shuffled assignment is not stable across scikit-learn versions. All verified single-model numbers in this report are computed on exactly these 1,979 images, so they are directly comparable. The final model additionally uses 5-fold cross-validation with the same grouping: every training image is predicted once by a model that did not see it, which gives an out-of-fold estimate on all 9,879 images with a standard error of about 0.17 points at 97% accuracy, versus 0.4 points on 1,979 images.

We also found that {{ eda.test_images_identical_to_a_train_image_raw if eda else 333 }} test files are byte-identical to a training file ({{ eda.test_images_identical_to_a_train_image_pix96 if eda else 352 }} after preprocessing) and {{ eda.test_duplicate_images_beyond_first_pix96 if eda else 163 }} test images duplicate another test image. The codebase contains two optional post-processing rules (copy the known label; share one prediction among identical test images). They are switched off by default; Section 5.4 states whether the submitted entry used them.

3. Architecture

3.1 Reference model trained from scratch: EmojiCNNv2

The team's first model (30 September) had three Conv-ReLU-MaxPool blocks without normalisation, global average pooling and a linear layer, trained with Adam at 1e-3 for 20 epochs; it reached {{ base.accuracy|pct(2) if base else "76.71%" }} and was still improving when it stopped verified. EmojiCNNv2 keeps the same philosophy (small, from scratch, explainable) and fixes what held it back: BatchNorm after every convolution, a fourth stage so the receptive field covers the whole 96 px canvas, AdamW with a OneCycle learning-rate schedule, and the augmentation above.

3.2 Final model: ConvNeXt-Tiny, fine-tuned end to end

ConvNeXt (Liu et al., CVPR 2022) is a pure convolutional network that borrows the macro-design of vision transformers: a 4×4 stride-4 "patchify" stem, four stages with [3, 3, 9, 3] blocks and widths [96, 192, 384, 768], and in every block a 7×7 depthwise convolution followed by LayerNorm and an inverted-bottleneck MLP (1×1 convolutions expanding to 4× the width with GELU), with a residual connection, layer scale and stochastic depth. Global average pooling, LayerNorm and a linear layer form the head; we replace the 1,000-way ImageNet head with a 7-way layer. The Tiny variant has 27.8 M parameters and about 4.5 GFLOPs per 224 × 224 image.

Figure 6. The final network. Five copies (one per fold) are trained; at test time their softmax outputs on the image and on its mirror are averaged.

Why a pretrained CNN, and why this one. The team's experiments isolate the ingredients reported: with the ImageNet backbone frozen, ResNet18 reached only {{ (rep.experiments | selectattr("id","equalto","E4_resnet18_frozen") | first).val_accuracy|pct if rep else "77.5%" }}, below the from-scratch CNN, because generic object features say little about rendering style; fine-tuning the same network gave {{ (rep.experiments | selectattr("id","equalto","E5_resnet18_finetune") | first).val_accuracy|pct if rep else "93.7%" }}. Among fine-tuned backbones at 128 px, ConvNeXt-Tiny ({{ (rep.experiments | selectattr("id","equalto","E6b_convnext_tiny_finetune") | first).val_accuracy|pct if rep else "95.9%" }}) beat ResNet18 and EfficientNet-B0 ({{ (rep.experiments | selectattr("id","equalto","E6_effnetb0_finetune") | first).val_accuracy|pct if rep else "93.1%" }}), with the largest gain on the minority classes; its 7×7 kernels see a whole stroke and its LayerNorm does not depend on the batch. Moving the same model from 128 to 224 px added another 1.7 points ({{ e8.val_accuracy|pct(2) if e8 else "97.57%" }}), mostly on Facebook and WhatsApp: 224 px is the pre-training resolution and close to the 240 px native size of the Meta and Mozilla files, so fine detail survives. Resolution, not depth, was the biggest lever after fine-tuning.

4. Metrics chosen

  • Accuracy is the competition metric and the headline number. On 1,979 validation images the binomial standard error at 95% accuracy is 0.5 points, so differences below about one point between two single runs are not meaningful; out-of-fold accuracy on 9,879 images has a standard error of 0.15 to 0.2 points.
  • Macro F1 and balanced accuracy because Messenger (5.9%) and Mozilla (4.0%) barely move the accuracy but are the hardest classes; macro averages weight them like the others.
  • Per-class recall and the confusion matrix to see which providers are confused; the meaningful pairs are within the same export family (Facebook / Messenger / Mozilla at 240 px, Apple / Google / Samsung at 72 px).
  • Log loss of the validation probabilities: averaging probabilities (soft voting) only makes sense if they are reasonably calibrated.
  • Paired counts (images one model gets right and the other wrong) when comparing two models on the same split, which is more informative than the difference of two accuracies.

5.5 What did not work

  • Frozen ImageNet features (ResNet18 as a fixed feature extractor): {{ (rep.experiments | selectattr("id","equalto","E4_resnet18_frozen") | first).val_accuracy|pct if rep else "77.5%" }}, below a 0.4 M-parameter CNN trained from scratch. Object-level features do not encode rendering style; the backbone must be adapted reported.
  • Resampling augmentation and label smoothing on ConvNeXt-Tiny: minus 1.5 points, with errors concentrating on Facebook → WhatsApp and Mozilla reported. Our exact-pixel augmentation is the response.
  • Voting with weaker members: adding ResNet18 or the small CNN to the ConvNeXt ensemble lowered accuracy to 97.3 to 97.4% reported. Averaging helps only between comparably strong models, which is why the final ensemble is five copies of the same recipe, one per fold; even averaging in our own earlier snapshots of those five models (Section 5.2) did not help.
  • The first baseline's training budget: with Adam at a constant 1e-3 and 20 epochs the September CNN was still underfitting ({{ base.accuracy|pct(2) if base else "76.71%" }}, train accuracy 75%) verified; BatchNorm and a OneCycle schedule, not more parameters, closed most of the gap.

7. Conclusion

Recognising who drew an emoji is a style-recognition problem, and the project taught us as much about the data as about the models. Looking at the files before the pixels showed a leak large enough to score {{ meta_format.accuracy|pct if meta_format else "far above chance" }} from dimensions and colour mode alone; deciding to neutralise it (white compositing, one canvas, pixels only) made every later comparison about what the network sees. On the modelling side the lessons were plain: a small CNN trained properly beats hand-crafted features by a wide margin; pretrained features only help once the whole backbone is fine-tuned; input resolution mattered more than the choice of architecture; and augmentations that resample the image remove the very detail that identifies the vendor. The final ConvNeXt-Tiny ensemble{% if fin %} reaches {{ fin.accuracy|pct(2) }} out-of-fold accuracy{% endif %}, separates the export families almost perfectly from pixels alone, and spends its remaining errors on documented look-alikes (WhatsApp's Apple-inspired set, the shared face conventions of Apple, Google and Facebook), which is a reassuring sign that it learned style rather than shortcuts.

With more time we would (i) train at the native 240 px for the Meta and Mozilla files instead of 224, (ii) try a two-stage classifier that first predicts the export family and then the vendor within it, as an explicit and interpretable version of what the network does implicitly, (iii) run a proper seed study to put error bars on the architecture comparisons that we currently cite from single runs, and (iv) replace the equal-weight vote with a learned combiner (a small transformer or logistic layer over the base models' outputs, trained only on out-of-fold predictions so that it never sees a prediction made on its own training image). Our own evidence suggests the gain would be small: an equal-weight vote of a DINOv2 model with the ConvNeXt entry scored {{ (N.public_lb.entries | selectattr("file","equalto","submission_dinov2_convnext_ensemble.csv") | first).public_score|num(5) if N.public_lb else "0.96881" }} on the public board, below the ConvNeXt entry alone, so a combiner would mostly learn to ignore the weaker member.
